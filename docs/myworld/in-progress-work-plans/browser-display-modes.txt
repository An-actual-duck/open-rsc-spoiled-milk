Presentation contract
- Fit tab is the default; Embedded is an explicit comparison view.
- The outer document owns the Fullscreen API and keeps a reserved control bar
  with Stop and Exit fullscreen. Requests occur synchronously from the real
  button gesture. Denial, unsupported APIs and Escape are handled without
  destroying or automatically restarting Java. Stop exits owned fullscreen.
- Browser-only JFrame setup removes virtual native decorations and pins the
  game window to the virtual desktop origin. Native desktop defaults are intact.
- The entire Java display, GPU canvas and readiness cover share one aspect-fit
  CSS transform. CSS resize/fullscreen does not request a larger framebuffer.
  Internal resolution, actual CSS size, fit offsets and DPR are exposed through
  runtime browserProof.displayLayout. Parent presentation records the view mode.
- CheerpJ 5 pointer/wheel dispatch subtracts its canvas client rect but does not
  divide by a CSS transform. Display capture normalizes clientX/Y before vendor
  handlers. Window/document readiness gates and the independent middle-button
  relay see original screen coordinates first. No vendor patch, duplicate
  synthetic event, keyboard lock, pointer lock or physical desktop input is used.
- A display/mode/resize transition cancels an active middle-button drag.
