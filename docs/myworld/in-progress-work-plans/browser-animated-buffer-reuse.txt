Browser animated world-buffer reuse

Worker ai-1, fix/browser-animated-buffer-reuse. BrowserWebGLBridge chunk-cache
methods only; no changes to sprite upload methods, browser JS, desktop rendering,
gameplay, server state or public deployment.

Problem
The browser used every animated storage/pose signature as a new resident key.
A changing windmill pose allocated another VBO/IBO/VAO and retained or evicted
the prior pose. The geometry still needs packing/uploading for each new pose;
this change removes allocation/cache churn, not animation work itself.

Identity and current content
The browser now shares production WorldChunkBufferKey.from(chunk,true):
- Static storage uses immutable signature/plane/role identity and retains the
  established draw-offset rebase behavior.
- Animated storage uses plane, center section, logical origin, object flag and
  role. Its cached entry records the last accepted exact storage signature,
  packed shape, material dependencies, settings and vertex offsets.
- Changed poses replace the existing same-shape buffers via the already-tested
  native replaceChunk contract. Pose updates bypass the settings-only repack
  budget so an old animation pose cannot remain on screen behind queued work.
- A changed pose also recalculates material dependencies even when the global
  texture metadata revision is unchanged. Material/settings changes still
  invalidate packing; unchanged content stays resident.
- Conflicting simultaneous animated chunks with one logical identity are rejected
  explicitly instead of silently drawing two instances from the final pose.
  Multiple scenery models already aggregate within their positional chunk.

Shape changes and ownership
The existing JS replacement API requires equal vertex/index byte lengths.
A shape change reserves the full additional allocation against the current
224MiB budget (old resource remains live), uploads/validates a fresh ID, commits
new Java metadata/accounting, then deletes the old ID. Allocation failure does
not commit the new pose. In-place GL update failure remains terminal/fail-closed
under the existing JS backendFailed contract; this does not promise GPU rollback
or recovery after partially executed bufferSubData. Context/session disposal
still belongs to the existing browser backend owner.
The immutable LRU/active policies, count/byte limits and texture cache remain.
