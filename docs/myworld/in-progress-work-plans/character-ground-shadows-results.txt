Standalone character ground shadows — November 13, 2026
======================================================

Status: owner-approved appearance; correctness, hardware pixels and final native
functional checks passed. Ready for manager integration. No public release or
server activation was requested by this work.

Result
------
Add one subtle, soft-edged ground circle per visible character: NPCs, summons
and players. The original gallery's armoured figures were simulated players;
the initial NPC-only filter excluded them. The corrected pass covers those
figures and real multipart NPCs without adding a circle per body part. The owner
approved the corrected gallery after reviewing it in Firefox.

Circles stay at interpolated character ground positions, follow a cheaply
sampled terrain tangent and scale within a small footprint bound. They remain
stationary relative to the feet rather than stretching with the sun. They are
an inexpensive grounding effect, not silhouette shadows or new shadow maps.
Characters need captured body layers; their layer alpha also scales the circle.
The ordinary first-person/hidden-body submission rules continue to apply.

Roof and lighting rules
-----------------------
Use the exact GeometryShadowRoofMask.Cache already used by native geometry
sunlight. An actor whose centre is covered receives no circle; remaining fans
are clipped to outdoor tiles so edges cannot bleed into adjacent roof coverage.
Positive roof declarations remain authoritative when roof geometry is hidden.
Use the frame's signed underground policy: negative levels receive no circle.
Shadow Off and classic lighting also disable it; Low and High retain the same
low-cost circle. The native opt-out is:
 -Dspoiledmilk.characterGroundShadows=false

This inherits existing roof metadata availability. It does not infer roofs from
walls or repair the previously deferred multi-storey roof-data gaps. The real
crowd captures happened to report no actors on declared roof tiles; controlled
production-mask GPU pixels prove the positive-coverage clipping/suppression rule.
Do not represent those crowd captures as a full in-game indoor-area audit.

Implementation and resources
----------------------------
mudclient samples four neighbouring elevations on its own thread. Scene attaches
immutable footprint metadata to Renderer3DFrame; the GL thread never reads live
gameplay terrain. CharacterGroundShadowMesh builds sixteen-segment fans, with
linearly fading alpha and roof-tile clipping, into reusable direct storage.
OpenGLCharacterGroundShadows submits the batch once, with ordinary depth testing,
blending and no depth writes, before the character sprites are composited.
VBO/EBO resources close with the resident world session. No sprite assets,
textures, shader maps, gameplay definitions, packet changes or server code added.

Storage is bounded: at most131,070 vertices at28bytes each, a sequential index
buffer at4bytes each, and up to65,536 body-face alpha entries. Normal scenes use
much less vertex storage. Staging grows only as needed and is reused. The pass
uses no additional world cache. Shadow Off avoids producer elevation sampling.
The software path retains its existing rendering. Browser presentation does not
generate or render these footprints; WebGL support is a separate follow-up.
