Private browser gameplay feasibility spike (work in progress)

Scope
Current maintained Java client runs locally in a real browser through CDN-loaded
CheerpJ. This is not remote video streaming and does not touch Oracle, the PC
rollback server, owner credentials, maps or player databases. Desktop builds,
defaults and source classes remain unchanged. Browser support is experimental.

Observed so far
- Actual LWJGL3 GLFW initialization in CheerpJ 5.0/Java 8 fails with
  UnsatisfiedLinkError: Failed to locate library: lwjgl.js. The current native
  GPU renderer is therefore not a drop-in browser option.
- Explicit software presentation reaches a rendered login screen. Real mouse
  and keyboard input, ordinary RSA login and the private server's current
  terrain protocol all work. The atomic scene fence matched 1021 objects and
  35 walls before a later background halo mesh operation failed.
- Shared material initialization on the bootstrap main thread and retaining CPU
  geometry capture did not resolve that failure. No readiness/authority gate
  has been bypassed and no scene has been fabricated.
- A small probe calling the actual ChunkMesh family normalizer reproduces its
  NullPointerException in browser Java 8 when non-null family arrays are used.
  The same probe passes 3400 main-thread and 3400 worker-thread cases on the
  desktop JVM. Browser Java-version/WasmGC comparisons are in progress.

Local experiment
  python3 scripts/browser-gameplay/start.py --name MY-FRESH-RUN
  Open http://127.0.0.1:8079/?mode=software
  Disposable account: browserdemo / BrowserProof13
  python3 scripts/browser-gameplay/stop.py OUTPUT-RUN-PATH

start.py performs maintained client/server builds and stages a fresh empty-account
world. It refuses occupied private ports and existing run names. It serves only
the copied client files on 127.0.0.1:8079; the separate private server binds TCP
43629 and WS 43529 on loopback. The game owns WebSocket decoding; a small browser
SocketImpl/native-method adapter preserves its ordinary byte-stream protocol.
No Tailscale account, key, tunnel or paid service is used.

The existing OptionalSslHandler needs a non-null SSL context even for plaintext
WS. The fixture creates its own short-lived localhost certificate solely for
that handler. It does not install trust or require the browser to accept TLS.
Private keys, copied game data, DBs, JARs, browser profiles and captures stay in
ignored output/tests/browser-gameplay-spike/RUN directories, never Git.

Browser captures use a disposable headless Chrome profile and CDP-generated
mouse/key events, never the owner's browser profile or physical desktop input.
  node scripts/browser-gameplay/inspect.mjs RUN native-probe 15
  node scripts/browser-gameplay/inspect.mjs RUN mesh-probe 15
  node scripts/browser-gameplay/inspect.mjs RUN software 50 --login
Optional comparisons: --java=11, --java=17, --wasmgc.
Actual private gameplay acceptance is pending; a login screen is not completion.

Checks
  node tests/myworld/test-browser-transport.mjs
Tests cover frame fragmentation, partial reads, a 1 MiB frame, signed byte
preservation, EOF and the receive-buffer limit. Browser runtime/source and
renderer evidence are recorded with each capture. Performance numbers from
this software/headless experiment are not certification of the GPU renderer,
large battles, mobile devices, browsers or public hosting.
