Representation and algebra
--------------------------
The original long[19] is retained literally when OFF. ON uses int[23]: fifteen
original int/boolean values and four signed64 values represented as high/low limbs.
The four wide values are x-originX, y-originY, top16-(originX<<16), and
bottom16-(originX<<16). There is no double rounding or wide arithmetic in their
construction. Java low-int subtraction intentionally wraps modulo2^32. Comparing
(aLow^MIN_VALUE)<(bLow^MIN_VALUE) computes unsigned borrow. The high word is
 aHigh-bHigh-borrow.
For unshifted values each high input is sign extension (n>>31); shifted originX
has exact words (x>>16,x<<16). The high subtraction fits int for every possible
input: conservative bounds[-32770,32769]. Reconstruction is the exact original
signed64 result, so the mapping is bijective even for MIN/MAX and negative values.

The original Arrays.hashCode(long[]) formula is preserved exactly: each wide
value contributes high^low; a sign-extended narrow value contributes n^(n>>31),
including negative source scales/starts. Hash accumulation/pixel hashing remains
Java32-bit wrap. Exact full source-pixel hashing AND comparison are mandatory;
mutable pixels and equal polynomial hashes never alias cache entries. Owned keys
still copy pixels, no origin/anchor/frame object is retained, and source changes
cannot be hidden by key reuse. The existing512bytes/layer budget estimate remains
unchanged: hits, misses, IDs, eviction order/cost and resource policy match the
frozen implementation. ON reduces metadata payload, not the declared cache budget.

ON-only source-count follow-up (after frozen8135)
------------------------------------------------

the double product must be<=2^21, then and only then it narrows to int. Every
accepted integer product is exactly representable. Any potentially inexact product
