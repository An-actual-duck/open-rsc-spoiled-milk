Representation and scope
------------------------
The complete accepted ee358e... catalogue has 1,400 resources and 19,001,439
vertices. Browser shader inputs use 23 of the 28 legacy float components;
components 9..13 are neither receiver nor depth-shadow attributes. The converter
refuses nonrepresentable values instead of quantizing them. Position, UV and
normal float32 bits are copied exactly, including signed zero. Material/raw/blend
colors must round-trip through float32(byte/255); light, model kind, material
family, variation mask and blend strength must be exact uint8 values. Negative
zero in those byte fields is rejected. Index and material-batch bytes are copied.

compact48-v1 byte offsets:
  0 position float32[3]; 12 UV float32[2]; 20 normal float32[3]
  32 material RGBA unorm8[4]; 36 raw RGB unorm8[3]; 39 base light uint8
  40 terrain blend RGB unorm8[3]; 43 model kind uint8; 44 material family uint8
  45 variation mask uint8; 46 blend strength uint8; 47 zero padding
The versioned 24-byte header declares magic, version, stride and three counts.
Legacy 112-byte Java/local/dynamic geometry is retained. Catalogue main-pass and
shadow VAOs bind their owned layout independently. No runtime scene repacking or
compact-to-legacy vertex expansion occurs. Shared allocation/residency accounting
uses actual allocated vertex plus index bytes; pending/cancelled uploads retain
the existing ledger and cancellation rules. Texture bytes are unchanged.

The immutable derivative manifest binds the exact canonical catalogue SHA,
client JAR SHA, source manifest/fingerprint, settings, layout and complete original
resource roster/hashes/counts. Resource paths and shapes are fixed. Downloaded
sidecar and payloads are length/SHA checked. Unknown active shader attributes fail
closed in compact mode. The stager checks converter/decoder source hashes and
full derivative inventory before staging. Canonical catalogue and RAM recipes
are not rewritten or rebound to a different Java executable. Stages identify the
current frontend and the distinct frozen Java source/artifact accurately.

Remaining acceptance and limits
-------------------------------
CPU bit proofs model normalized byte inputs; actual hardware shader conversion,
pixels, depth silhouettes/alpha cutouts, picking, animation, actor/VFX overlap,
context reset and live loading still require manager verification. Use legacy
and compact controls on the same artifact, with identical route/view/fog/budget.
Record actual GPU ledger/queue/transient peaks and CPU/frame-time distributions;
absence of GPU timer extension must be stated. No FPS gain is claimed. Compact
format primarily reduces geometry upload/storage bandwidth, and does not promise
lower VM/PSS/total VRAM. Do not change 512MiB default capacity based on full-file
size math; any 256MiB proposal needs separate selected-scene capacity evidence.
