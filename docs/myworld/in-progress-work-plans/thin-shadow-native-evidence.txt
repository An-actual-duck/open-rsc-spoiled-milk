Implementation and tests
  capture/preview --dump-fences enables the export; default behavior is unchanged.
  It resolves effective materials through the actual renderer helper, then
  selects checked materials 10/12 from every non-terrain kind. It never assumes
  the raw texture ID alone identifies the GPU material.

  Scene.getRenderer3DFrame can expose a frame while endScene is still building
  it, before resident chunks are attached. The new exporter instead polls for
  an already-published pending frame under the existing presenter frameLock,
  with a three-second deadline. The lock covers only a pointer/eligibility read;
  no file I/O, GL calls or copying occurs under it. Exported chunks and textures
  are immutable and separate from released pooled face storage. This is an
  observer correction, not a gameplay readiness or ACK change.

  tools/renderer-benchmark/analyze-fence-export.py CAPTURE writes a JSON summary
  to stdout and rejects missing references, duplicate pixels and incomplete
  texture grids. Four focused tests validate these guards and source alpha runs.
  The existing fourteen private process/report guards still pass. Python syntax,
  Java 8 bootstrap compilation and git whitespace checks pass. The complete
  native export validates the new flag and publication observer end to end.

  Workspace-layout check still reports inherited old ai3 output-root entries.
  New outputs use only declared tests/builds categories; no old data was deleted.
