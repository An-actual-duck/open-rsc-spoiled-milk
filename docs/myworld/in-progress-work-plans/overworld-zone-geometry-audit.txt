Overworld single-zone geometry audit — READY, audit only

The entire authored overworld is materially larger than one current view. With
existing expanded geometry, surface terrain plus scenery/boundaries requires
1.888GiB of GPU vertex/index capacity. Including upper-floor dependencies raises
that subtotal to2.053GiB, or2.080GiB with current positive-edge stitch duplication.
These are mesh subtotals, not a whole-client memory budget or proof of performance.
No zone, renderer, cache, map, server or product setting was changed.

Source-bound measured method
----------------------------
Full-source production JAR0409c558246b5652a70794f7b99fff9801729845a3f1d6d72dd4b0fe6574041b
matches every current Client_Base/PC_Client Java source hash. The audit compiles
only new test harnesses against it; no runtime classes are replaced or modified.

For each storage sector, actual NativeLayeredTerrainChunk/Snapshot decoding and
World private CPU-window/terrain/wall/roof/GPU-mesh builders run over its3x3 input.
Triangles are assigned by centroid to exactly one central24tile canonical cell.
Only the central48tile domain is counted, then split into four cells, so adjoining
windows do not multiply the whole3x3 mesh. Signed coordinates use explicit sector
identities; negativeY19,-1 is included. Missing-neighbor void padding is retained
and reported:84L0 edge sectors have at least one missing neighbor.

The actual production positive-edge presentation crop is also called separately.
It allocates compact selected-triangle arrays, not unused full3x3 vertices. Its
preceding one-tile stitch strips cause additional ownership overlap; both compact
canonical and positive-stitch costs are recorded. Canonical counts are not passed
off as the exact current overlapping residency representation.

UpperL1/L2 use floor-local wall/roof topology without upper terrain. This measures
source topology/counts; it does not prove that floor-local coordinates equal the
stacked roof elevations used when viewing upper stories from the ground.

Scenery uses actual models.orsc decode, mudclient normalization/material/interaction
and explicit generated-model hooks, then RSModel.buildRenderer3DObjectChunkMesh.
A bare Unsafe-allocated client is used solely for these source-reviewed pure
methods; no client constructor, login, scene, browser, networking or GPU runs.
Current boundary static-presentation quad/material behavior is separately used.
All866 unique scenery/boundary definition IDs resolve. Missing archive entries
would be reported unresolved; no placeholder cube/zero is treated as resolved art.
Manifest placement counts are independently supplied by ai2 and hash-bound in the
receipts. All counted scenery/boundaries lie in authored sector coverage.

Non-mesh allocations and uncertainty
-----------------------------------
Material batches are separate. Terrain raw-key group metadata totals305,720/
10,420/2,500bytes under the reported conditional grouping. Actual texture-atlas
resolution/transparency can alter grouping/skip behavior. The report also supplies
an absolute one-batch-per-triangle bound, not a claim that current content uses it.
Textures/mips, sprite atlases, actors/NPCs/players/summons, spells/VFX, animation
variants, shadow maps, depth/MSAA/color buffers, driver overhead and command
staging are excluded from vertex/index figures. Manifest placements are a named
subtotal; independent runtime-addition reconciliation must remain explicit.
The native audit time is not a browser initial-load or FPS forecast. No fullzone
allocation, actual GPU-fit test, render-distance change or performance test ran.
