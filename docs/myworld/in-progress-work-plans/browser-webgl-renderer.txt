Browser GPU renderer continuation — private development
=======================================================

Scope
-----
The maintained Java game now has an optional synchronous browser presentation
sink at ScaledWindow.setGameImage. Desktop presentation remains the default.
The sink borrows immutable Renderer3DFrame/Renderer2DFrame snapshots; the registry
releases pooled 3D ownership in finally on normal, null-image and failure paths.
WebGL2 receives primitive arrays and uploads/copies them before native calls
return. This is local Java game execution and browser GPU rendering, with the
normal private WebSocket server protocol and native world authority intact.
No desktop video stream, owner account, public server or production DB is used.

Renderer data
-------------
Resident geometry uses the production vertex/material/normal packer, camera
matrix arithmetic and GLSL resident shader strings. A small syntax adapter
converts GLSL120 to GLSL300es. Chunk storage signatures and presentation rebase
offsets identify resident GPU buffers. The implementation preserves original
texture pixels and game sprite artwork. RendererFrameLighting scopes the actual
immutable frame so signed negative levels retain the current neutral-light rule.

World sprites use the existing owned multipart snapshots, production composite
texture builder, and production top/bottom depth estimator. Camera-space quads
receive ordinary GPU depth testing against the resident world. Scene software
sprites are suppressed only through the existing explicit replay capability.
UI remains a software layer. An unused direct-RGB framebuffer high-byte marks
cleared world background; real black pixels remain opaque. getRGB cannot retain
this metadata, so the bridge validates and borrows the packed direct int buffer.
Partially transparent UI composed against the old software background still
needs a fuller command/coverage renderer; full visual parity is not claimed.

Resource ownership
------------------
Scene/chunk/viewport/texture and sprite-atlas dimensions are bounded. The geometry
and world-texture budget is256MiB; the sprite atlas is separately16MiB and the
software overlay at most8MiB. These figures exclude driver/program overhead.
A new frame's active chunks are protected. The optional LRU reserves32MiB for
world textures and evicts inactive buffers before an upload exceeds its chunk
byte budget. The earlier active-only policy remains a controlled comparison.
No referenced chunk may be evicted while the current frame needs it. Context
loss/errors are surfaced; the prototype requires a fresh session to recover.

Work remaining
--------------
Shared production lighting/shadow data and browser modules are a separate focused
worker slice. Their integration and actual GPU visual checks remain pending.
A browser-only optional declaration to omit an unused CPU depth raster is being
prepared for a separate old/new test, with desktop/editor/source defaults kept.
It is not enabled by default before interaction and GPU-occlusion evidence.
Hardware/browser/device coverage, broader combat/content, context recovery and
public TLS/networking/distribution acceptance remain future work. This document
does not claim the owner's full visual/performance goal has been achieved.
