Whole-overworld prepared RAM: private measured results, November 11, 2026
=======================================================================

The full RAM prototype reduced warm boundary pauses on the tested host, but
still pauses for roughly 0.3 seconds and does not deliver 60 FPS. It remains private,
explicit wholeram=on and default OFF. Public server, maps, ordinary client choices
and defaults were unchanged. Owner travel/visual feedback is pending in the
fresh final preview, now ready and released to the owner. It is not adoption.

Startup and memory tradeoff
----------------------------
Actual Java source/prepared readiness reported 1797 files, 445 recipes and 1330
query cells. Preparation took 14.587 seconds on ON and 15.089 seconds on repeat.
Whole startup scripts took 73.84/56.99/73.07 seconds ON/OFF/ON, including artificial
settle/typing time; those are not clean load-time measurements. The initialization
wait is a real tradeoff, not removed work hidden from the report.

Retained source+prepared primitive payload is 275,990,134 bytes (263.20 MiB):
46,101,734 source-bundle bytes +229,888,400 prepared primitive bytes. This is a
lower bound excluding objects/headers/maps, mutable active models, CheerpJ/VM,
virtual-filesystem copies, transient buffers and browser/driver memory.

Owned Firefox-tree PSS observations after route/stationary were 1896.18 MiB ON
and 1840.91 MiB OFF; RSS 2689.67/2660.29 MiB. PSS covers the entire owned tree, not
Java heap. RSS can count shared pages repeatedly. The observed 55.27 MiB PSS
difference is NOT standalone cache cost or a memory-budget promise. Host GPU
counters include unrelated applications. One host with 12 GiB primary VRAM does
not establish capacity/performance for lower-memory machines or a long soak.

Correctness, scope and preserved failures
-----------------------------------------
Complete source/reader, real-basis World parity, decoder and immutable wrapper
checks passed; the summary records 204,583 independent actual-basis checks,
33 full-reader checks,1,569,131 wrapper checks and 20,484 decoder checks.
Source/recipe/use counters advanced in actual play, rather than staged-file
counts being treated as readiness. Raw source alone never meant prepared CPU.

Actual scope smoke reached global L0, signed -1 and signed 10, then returned to L0.
Outside global L0 the original local path remained active, the full RAM/GPU data
stayed retained, and recipe/hit counts stayed unchanged until L0 returned. This
is fallback with retained resources, not extra-level prepared residency. Selected
source/CPU cases have parity proof; all 445 recipes were cooked, but not every
recipe received an independent complete pixel oracle. Tree contextmenu/Chop was
observed; stump/respawn and a complete hardware door lifecycle were not proven.

Earlier rejected startup attempts remain preserved: first roof-visible data
correctly refused a hidden-roof client; a later attempt exposed the original
zero-carrier-basis assumption. Matching hidden-roof cooks and checked logical to
legacy-carrier adaptation resolved these causes. They were not evidence of an
unsupported CheerpJ decoder or browser out-of-memory failure.

The later explicit Stop discrepancy was a stale parent proof: its old-session
message filter correctly ignored the disposed child's queued final message.
The now-merged parent fix clears its own readiness synchronously while retaining
historical counts; 77 queued structured-clone lifecycle cases pass and the old
source fails. No iframe/process leak is inferred from that stale receipt.
