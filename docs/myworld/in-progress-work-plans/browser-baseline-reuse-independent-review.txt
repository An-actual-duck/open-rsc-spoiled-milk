Safety conclusions
------------------
Reuse never supplies scene authority or GPU readiness. It chooses an existing
clone only for an exact global placement key and verified source/template/raw
instance geometry; otherwise the original clone path runs. Animated models,
changed transforms/scale, mutable geometry/material/pick bounds and ambiguous
keys cannot be silently treated as identical. Duplicate physical references
refuse the complete optimization, avoiding altered duplicate-removal semantics.

Scene/collision handling still removes old collision flags before reconstructing
the incoming ordered list, assigns the fresh picking index, samples current
terrain height and rebuilds light/transformed normals through the maintained
materialization path. Walls remain newly constructed. Source proof checks are
performed once per template per baseline; they do not replace exact raw target
comparison. Source-array snapshots are owned copies with exact float bits.

Level 0, global native source, current requested level, whole-RAM, static-scene,
private browser presentation and no live terrain patches are all required.
Negative/high levels, non-global sources, source/settings changes, resets and
capacity refusals clear the workspace or take the literal fallback. Ordinary
mode does not select reuse even if the reuse JVM property is set.

The conservative proof workspace allowance is capped at 16MiB with 4,096 objects
and 512 templates; proofs are admitted before copying, account for replacement
while an older proof remains live, reserve transient map slack, and unused
proofs are dropped after replay. This is a conservative scoped workspace budget,
not an exact Java heap or total application memory measurement.
