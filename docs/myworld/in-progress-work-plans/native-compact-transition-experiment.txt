-Dspoiledmilk.nativeCompactGeometry=true selects an exact 52-byte native vertex
instead of 112 bytes where eligible. Position, atlas UV and normal remain float;
19 fields use exact admitted unsigned bytes, including independent material color
and texture light. Blend strength is normalized, model/family/mask are not.
Negative zero in byte channels and nonfinite/unrepresentable values reject;
float position/UV/normal channels preserve negative zero. A late rejected vertex
regenerates the ENTIRE legacy chunk. Main and near/far shadow bindings agree.
Eligibility requires atlas coordinates, resident shader, unbaked directional
lighting and no projected shadow-proof path. Other modes retain legacy layout.
The requested representation participates in resident-cache matching. Browser
modes cannot enable this native control. This is not the browser 48-byte layout.

-Dspoiledmilk.nativeMaterialBatchReuse=true independently reuses first-pass
triangle-to-batch references in the second material-index pass, preserving exact
first-seen batch order, indices and bounds. It is capped at 262,144 triangles,
with literal fallback above the cap. Browser modes ignore it.

-Dspoiledmilk.nativeGeometryDiagnostics=true records at most 4,096 per-frame
upload rows: CPU packing, index copy, grouping, GL submission, bytes, compact and
legacy vertex counts, chunk count and resident/scratch bytes. No synchronous GPU
query is added. GL submission CPU time is NOT GPU completion. Existing asynchronous
GPU timer ring supplies the separate diagnostic GPU observations.

Memory accounting
-----------------
112->52 is a 53.57% vertex-byte reduction; the complete observed upload including
both unchanged index streams is 141,441,120->70,720,560 bytes (50%). Matching
resident geometry is 465,035,040->232,517,520 bytes, including both index streams.
This is geometry residency, NOT total GPU/driver/atlas memory. The retained direct
scratch ledger rises 17,825,792->26,214,400 bytes because legacy fallback scratch
remains beside geometrically growing compact scratch. The ledger excludes old
replaced direct buffers awaiting GC, temporary diffuse/shadow arrays, maps and
batch records, and the independently bounded batch-reuse reference array. Do not
claim a total CPU-memory reduction. No evidence supports changing cache residency
or contention: the prior measured lock waits were negligible.

Encoder investigation and useful next direction
-----------------------------------------------
The first e7bc449 pilot validated every byte twice, producing140.369 ms packing
versus44.815 OFF; its compact max gap301.21 ms. It is not pooled with5820 results.
The optimized encoder uses one admission per byte and a256-entry exact normalized
float-bit table; this reduced but did not remove the overhead. Absolute writes
preserve the buffer position on rejection, and full fallback rewrites the chunk.
One final bounded microkernel tried native-order int[13] staging plus bulk
IntBuffer.put. Three fresh JVM medians,131072 vertices: scalar5.738/5.331/5.274 ms,
bulk6.529/6.145/6.036 ms. Exact byte/fallback proof passed, but bulk is slower.
It remains a benchmark fixture only, not a new runtime or another route campaign.
See output/tests/native-compact-packing/run-{1,2,3}.csv.

Most eligible fields originate as integers: writeUnbakedChunkMaterialColor
extracts raw RGB, writeChunkShaderInputs emits integer legacy light, raw RGB,
model/family/mask, terrain RGB/strength, and writeChunkTextureLight emits constant
1.0 in the eligible unbaked path. The float writer then converts them to normalized
floats, and the compact encoder reconstructs/admission-checks them. A future shared
typed writer could emit original integers directly, preserving one material
formula implementation and exact range rejection (especially future masks, enum
IDs and strength). Position/UV/normal remain float. Legacy/baked brightness/light
paths can produce arbitrary floats and must retain fallback. The result rejects
this float-roundtrip implementation, not compact geometry as inherently slow.

Coherent scheduling: tested laboratory rejection, not production integration
---------------------------------------------------------------------------
NativeTransitionUploadPrototype is isolated under tools/renderer-benchmark/orsc;
no presenter uses it. Immutable copied inputs, pending/live separation, bounded
plane/total bytes, bounded GL calls and atomic completion are exercised. Identity
covers source/level/settings/atlas/context; same-source pose and animation coalesce
without restarting static work. Actual identity changes cancel; publication needs
the latest frame token and external ownership assertion. Pending input/picking is
blocked. Tests cover stale generation, failure, cancellation, cleanup, copied
source mutation, animation starvation and latest-animation publication.

Real GL prototype submission, synthetic201 planes/67 chunks totaling141441120B:
4MiB per tick:34 ticks,33.101 ms submission total,max tick2.598 ms,
              upfront immutable copy37.731 ms,modeled60Hz readiness566.667 ms.
16MiB per tick:9 ticks,16.564 ms submission total,max tick2.136 ms,
              upfront copy25.560 ms,modeled60Hz readiness150.000 ms.
Per-call cap64KiB,soft3ms check,max32 allocations/tick. A GL call is not preemptible.
No timing waits for GPU completion; buffer readback validation is outside timing.
See output/tests/native-transition-prototype/{cpu.log,gpu.log,gpu/slices-*.csv}.

This can smooth submission while delaying useful-world readiness/aging the old
image. Modeled60Hz values are NOT measured game/display latency. Actual CPU
packing/grouping and real Frame.release/pool ownership are not scheduled here;
the upfront copy is real and must not be omitted. Live GPU data is only1KiB in
this fixture, not465MB. Real old residency plus two141MB pending copies exceeds
512MiB before other resources. The game atlas can mutate UV/material ownership;
old VBO retention alone cannot preserve a complete old scene. Production frame,
camera, picking/input, atlas/material and shadow ownership remain unimplemented
and unvalidated. A normal launcher skips fallback raster, so simply enabling the
old3ms upload flag is unsafe. No production scheduler or first-new-frame speedup
is claimed. Parent accepted this bounded rejection rather than a speculative
full lifecycle rewrite without favorable cost/readiness evidence.
