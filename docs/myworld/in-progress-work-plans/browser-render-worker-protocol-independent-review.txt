Independent test obligations
----------------------------
Capture: use real offset typed views with arbitrary int/float raw bits, including
NaN payloads, negative zero and shared disjoint input storage. Verify owned
packet data survives mutation of every source immediately after capture; never
transfer/detach Java source buffers, never retain borrowed views until a later
frame. Intrinsic view shape must govern actual bounds and copying rather than
own getters/iterators. Bound all lengths/counts/totals before allocation/copy.

Ordering: initialize must return actual worker MAX_TEXTURE_SIZE before Java
uses it; shader initialization is asynchronous. Record resource upload/delete/
replace/reuse in exact call order, including resources created before the first
draw. Draw cancellation must not cancel its resource prefix or permit stale ID
reuse. Multiple native callbacks in one Java frame produce one bounded owned
packet. Initial scope is full C/T only, overlay delta OFF: no second partial-
upload ACK/history system.

Slots: two in-flight slots are a capacity limit, not a claim of two frames
presented. Slot release and presented counters require an exact worker execution
completion ACK with matching session/slot/frame identity. A queued/postMessage
return is not an ACK. Duplicate/stale/foreign ACKs cannot release slots or count
presentations. Backpressure must bound pending work before further staging can
be overwritten. CPU tests will explicitly hold both ACKs and observe blocked
third admission; inspect one completion at a time and disposal while blocked.

Failure: malformed packets reject before GPU-side dispatch/allocation. Posting,
worker initialization, decode, backend execution, context loss and disposal must
reject outstanding promises and wake blocked producers without false presented
ACKs. No later dispatch may succeed on the poisoned session. Borrowed inputs may
not survive in error objects/closures. Recovery requires explicit new ownership.

Display: preserve logical viewport, physical drawingbuffer, DPR/layout and
resize epoch/order. An1843x1037 physical main canvas must not silently become a
960x540 worker drawingbuffer. Old-size completion cannot publish as a new resize
epoch. Worker-visible time/presented/frame-age/drop counters must be distinct
from Java producer FPS. Existing WebGL resource/pixel/shadow quality stays in
scope, even if protocol CPU tests alone cannot prove it.

Initial source observations (base58c, not candidate findings)
----------------------------------------------------------
tools/browser-gameplay/web/webgl.js initializes shader/backend state and returns
actual MAX_TEXTURE_SIZE from initialize. It receives resources before drawing,
retains explicitly copied chunk metadata, and receives context loss outside the
native endpoint flow. Its physical output sizer currently reads canvas DOM
layout. The proxy/worker protocol therefore needs explicit initialization
round-trips, durable ordered resource commands, asynchronous fatal messages and
main-thread display metrics. These are obligations to verify, not reported bugs
in a candidate that has not yet been checkpointed.

Proof details
-------------
The raw-byte oracle uses real nonzero-offset Float32/Int32 views containing
negative zero and noncanonical NaN payloads. Own forged/throwing shape getters
do not change intrinsic source bounds. Shared source aliases become separate
owned copies; mutation after capture cannot affect packets. Real Node
structuredClone transfer detaches ONLY owned command storage, never original
source storage. A second real transfer returns the owned copies; immediate
0xa5 overwrite and later reuse still yield exact new packet data. This proves
JS ownership/structuredClone behavior on Node, not Firefox transfer performance.

Two packets can remain unACKed; a third producer waits until one exact completion
ACK arrives. No posted packet counts as completed. Initialization's scalar result
stays pending until its own ACK. Bad ACK version/id/frame/layout, duplicates,
missing/wrong-size/duplicate/shared/fake buffers terminate before successful
credit or pool admission. Returned buffer count/order/length/unique identity are
validated against that packet's recorded capacity. Identity is not physical
cross-transfer provenance: a same-sized new genuine buffer can provide usable
capacity, because every byte is overwritten before reuse and its old contents
are never interpreted as acknowledged pixels. The executor is trusted same-origin
code. This is not an adversarial cross-origin security protocol.

Pool1024-entry cap is exercised. Source separately caps retained pool bytes at
16MiB; total owned payload capacity is TWO64MiB in-flight packets plus ONE64MiB
producer plus16MiB pool=208MiB. It is not a process-memory ceiling: backend owned
copies, resources, strings/objects, browser/driver storage and GC peaks are
additional. Tests also prove the1024-command producer/envelope limit, aggregate
payload rejection BEFORE any byte-copy, and staging/pool/pending cleanup on error.

Ordered upload/delete/reuse is preserved. Entire structural/schema/cap/method-
availability preflight rejects a malformed LAST command without executing a
valid resource prefix. Backend semantic validation remains authoritative: a
schema-valid but semantically bad later resource can follow an executed valid
prefix before throwing. The executor then poisons and produces no successful
ACK; GPU-frame/resource atomicity is NOT promised. No continuing frame-cancel
operation silently drops staged resources. Failure/dispose abandons the entire
session; any recovery requires fresh ownership/backend initialization.

World present is captured until its subsequent frameWork; the resulting packet
contains both in literal order. A deliberately unresolved fake frameWork delays
the completion promise/ACK even after present ran, and exact Float32 raw bits and
Int32 counters reach the backend. Result queries (initialize, planWorldSprites)
are explicit synchronous-result barriers and can produce an extra command packet
before the final presentation packet. Therefore one Java world frame is NOT
claimed to always equal one IPC packet. Two-slot backpressure and ACK counters
apply to packets; completedFrames counts presentation-complete packets. These
are worker backend-call completions, not GPU-fence or compositor-scanout proof.

Main-side fakeWorker tests execute the actual adapter factory. They cover
startup failure, normal result completion, readback worker death, readback post
failure, confirmed-disposal worker death and cleanup of ResizeObserver/window
listeners. Callback/layout/actual injected byte-copy/post failures reject held
result barriers and blocked producers, clear staging/in-flight/pool capacity,
and prohibit successful continuation. Context-loss is simulated by the fatal
message route; actual browser context-loss behavior remains a manager gate.

Resize layout epochs reject changed geometry under an old epoch, with zero
backend prefix; later epochs update explicit physical sizing. A1843x1037 CSS
snapshot yields1843x1037 physical output for960x540 logical content, rather than
silently using a worker-global960x540 fallback. Actual maximum texture capability
is returned by initialization; pure sizing uses that capability. Real display,
DPR, input mapping and odd dimensions require the separate GPU/DOM review.

Closed diagnostics tests exercise omitted unknown cache/plane objects, bounded
known metadata/string/array/field budgets, equal consecutive sample intervals,
no duplicate stale samples and full-ring tail accounting. Sample payloads also reject typed planes/nonfinite or negative intervals,
wrong policy kinds and malformed Java14-value work rows. Each accepted work row
is copied, so mutating its source cannot change the snapshot. Top-level field
and combined string budgets reject oversized metadata. This remains an internal
maintained backend diagnostics interface, not an external security boundary.

Returned-buffer backend retention review
-----------------------------------------
Read-only source inspection found no retained alias to a command-owned buffer in
the reviewed backend path. webgl.js copies lightingFrame values and chunk batch
metadata; chunk color bounds are derived own arrays. browser-lighting copies
mask bounds/values; browser-shadows copies values. browser-sky copies ranges and
frame values and synchronously uploads vertex/palette data. Sprite atlas plan
stores scalar-derived metadata, returns its own missing-ID list, copies quad
coordinates and synchronously uploads pixels. Full overlay prepare uploads T
immediately and retains scalar declaration/token metadata; present consumes C
synchronously. Frame pose/work history copies arrays/scalars. Raw geometry/
pixel planes go to synchronous GL uploads and are not cached as JS input views.
This source review supports safe transfer-return after backend completion; the
manager GPU oracle must still mutate/reuse returned storage and render unchanged
resources to prove actual browser/GPU equivalence.
