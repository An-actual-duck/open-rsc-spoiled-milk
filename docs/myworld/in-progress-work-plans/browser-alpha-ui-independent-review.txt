One reproduced issue
--------------------
A pending fullscreen request from a discarded runtime could undo a successful
replacement runtime's fullscreen. The outer player element is shared across
sessions. Sequence: request A remains pending; Restart dismisses it; request B
succeeds; A then resolves and its stale-completion branch unconditionally exits
fullscreen. The independent production-module test reproduces that exact loss of
new ownership. This is a display lifecycle race, not a gameplay/server failure.

The independent test is tests/myworld/browser-alpha-ui-review/display-generation.mjs.
Original failing evidence is ai3/output/tests/browser-alpha-ui-review/display-generation.log.
The implementation worker was asked to preserve late-after-Stop cleanup while
preventing obsolete completion from exiting a newer fullscreen request.

Resolved in final exact UI READY 7fd6a63a142d05f6517e2fb968e74afbddc5cfcc.
The display module separately tracks entry ownership and invalidation generation;
obsolete completions only clean up fullscreen when no newer owner wants it.
The independent race test passes. The implementation adds coverage for both
replacement success and cancellation of all pending owners. Java bytes remain
identical to the canonical JAR above. No remaining review blocker was found.
