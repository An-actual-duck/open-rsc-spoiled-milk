Actual archive rehearsal
New tests/myworld/rehearse-player-package.py accepts an actual candidate output
directory, an older Java archive and an exact expected source commit. It reads
the original archives without modification, verifies their SHA256SUMS and
consolidation receipt, CRCs, safe member paths, shared client JAR/source/endpoint,
native payload entries, release marker, ordinary production entry point,
installed-map manifest and complete package fingerprint. It rejects packaged
credentials, UIDs, saved client settings and databases.

The untouched POSIX updater is executed from a disposable extracted older
installation. A PATH-local curl bridge allows exactly the original GitHub feed
and candidate asset URLs, translating those two to an ephemeral 127.0.0.1 HTTP
fixture. Other URLs are refused. Proxy and inherited runtime overrides are
scrubbed. No production updater URL override or source edit was introduced.

Checks cover:
- Universal clean extraction with all three launchers and bundled Windows JRE.
- Linux launcher and macOS shell delegation from paths containing spaces.
- The released older updater installing the actual candidate Java archive.
- Synthetic saved Low shadow settings, preferences, UID and credentials retained
  byte-for-byte across upgrade. Off/Low/High settings then remain unchanged on
  subsequent ordinary launcher runs. No real saved identity is read or copied.
- API failure, missing asset, download 404 and invalid ZIP refusal before install;
  every pre-existing installed file remains byte-identical for each case.
- A newer candidate does not downgrade to the older feed version.
- Source archive hashes remain unchanged after the full rehearsal.

The Java executable in this helper is an argv recorder. It proves the shipped
POSIX launch scripts reach the expected JAR, cwd and release options without testing
flags or a forced shadow quality. It does not start a game, prove native OS/GPU
compatibility or contact the game's endpoint. Core's actual Java 21 candidate
startup and renderer native fixtures provide separate coverage.

Runtime and platform limits
The planned bundled Windows runtime's java.exe -version passes under Wine 9.0:
Temurin 17.0.20+8. This used a NEW task-owned WINEPREFIX under the declared test
output, DISPLAY empty, disabled Wine Mono/MSHTML/menu-builder integrations and
no owner's Wine configuration. Its task-owned Wine processes exited. The exact
java.exe SHA256 is 5b463cad4fcd8e4c655cc1c6f45a3b2ebb002adac94ebad2fdaa4f43e2aee211.
This is a Wine CLI/runtime smoke only, not a Windows game or graphics test.

Native Windows and macOS graphics, drivers, focus and their real filesystem
semantics remain unverified on this Linux-only host. A packaged native library
being present is distinct from running that platform. The POSIX updater has no
transactional post-copy rollback; tested failure safety is limited to the
explicit pre-install refusals above. No unsupported broader rollback guarantee
is made, and no updater redesign is included.
