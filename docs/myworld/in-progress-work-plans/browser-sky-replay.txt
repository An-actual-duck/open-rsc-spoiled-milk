Browser world-sky replay: focused implementation and review handoff

Scope
The default WORLD_DOME sky uses one shared WorldSkyGeometry source for native
OpenGL and browser replay. The native state/matrix envelope remains unchanged;
only its private geometry/color emission moves into this source. BrowserSkyData
caches the complete dome, Milky Way, stars and clouds, then updates the original
color slots and native projection/view matrix per source frame. No alternate
sky appearance or reduced-content replacement is introduced.

Integration contract (bridge/main webgl wiring owned by the renderer worker)
Java: retain one BrowserSkyData. Call prepare(frame) while that immutable source
frame remains valid. The helper binds/restores RendererFrameLighting itself.
Frame exposes enabled, values[20], palette[4096], geometry and ranges. Arrays are
borrowed until the next prepare/clear: upload or copy synchronously, never retain
them in an asynchronous queue. geometry/ranges are nonnull only after a cache
build (first enabled frame, radius change or clear).

values: 0 enabled; 1 night layers; 2 cloud layer; 3 palette count; 4..19 native
projection * translation-free sky-view matrix in column-major order.
geometry: float stride4 [x,y,z,paletteSlot], expanded triangles.
ranges: four int stride3 [firstVertex,vertexCount,blendFlag], in order dome,
Milky Way, stars, clouds. The dome is opaque; all other layers use source alpha.

JS: import createBrowserSky(gl,{stats}); initialize once. On changed geometry,
call uploadGeometry(geometry,ranges,values[3]); then prepare(values,palette).
After the parent clears its color/depth attachments, call draw() before world
geometry. The sky disables depth test/writes, so it does not take ownership of
the world's depth buffer. draw restores program, VAO, texture unit/binding,
depth test/write, color mask, culling and blend factors/equations.

Lifecycle and failure rules
An absent/disabled source frame should call prepare with values[0]=0; do not
reuse the last visible source frame. Negative signed levels always suppress sky.
The existing primary-world terrain plane/packed-origin heuristic is preserved
(including its upper-level limitations). SCREEN legacy sky is unsupported here;
it is nondefault and should be reported/fallback explicitly, not silently
represented as WORLD_DOME.
Viewport resize only changes the native matrix. Fog-distance/radius changes
rebuild bounded geometry; tone/day/night changes update the color palette and
layer flags without regenerating vertex positions. Native matrix helpers are
called through cached reflection, not duplicated browser camera formulas.

A full world-resource/context reset must call BrowserSkyData.clear() before the
next export. On WebGL context loss, stop presentation, dispose the old module,
recreate it after restoration, and clear the Java cache to force geometry upload.
Initialization failure makes the JS instance unusable; dispose/recreate it.
Geometry replacement failure keeps prior GPU resources valid and accounting
unchanged. Java has already committed its cache when it exports changed data:
propagate the upload failure and clear/retry or restart; never silently continue
with mismatched old GPU geometry/new frame metadata. dispose is idempotent.

Bounds and costs
One cached geometry radius, at most 65,536 vertices * 16 bytes (1 MiB); palette
1024 RGBA32F texels (16 KiB). Geometry replacement temporarily permits two such
buffers plus palette: 2,113,536 accounted bytes maximum. Driver/program/VAO
bookkeeping is additional and not estimated as zero. The palette texture uses
unit0 only inside its own program and restores the prior binding. It consumes
no world-program sampler slots. At most four draw calls per sky frame.
There are small per-frame Java Frame/palette-sink and native matrix arrays plus
reflection calls, and JS matrix/value copies; this is not an allocation-free
claim. Full geometry/trigonometry loops run only at cache rebuilds. Native
Sink dispatch overhead and actual browser GPU throughput remain unmeasured.
