Bounded next experiment and proof obligations
--------------------------------------------
1. Establish the explicit spritekeylimbs=on control first. Shadow-plan2D cells
   from existing writer hooks without changing pixels/GL. Record selected union
   area, rectangle count, fallback reason, actual bytes/calls and marking cost.
   A32x16 tile grid is a reasonable starting hypothesis (1,020 cells at960x540),
   not a chosen optimum. Bound masks, rectangles, area, call count and allocations.
2. Preserve last ACKNOWLEDGED CURRENT-touch mask, unioned with the new current
   mask, so disappearing UI/effects upload cleared RGB/T. Never ACK the larger
   upload union. Unsubmitted frames must not advance GPU history. Same-size owner
   changes, resize, reset, opaque/retained modes, holds and malformed/unsupported
   writers must retain authoritative invalidation/full fallback semantics.
3. The old cached contiguous linear interval is valid for whole-width row blocks.
   It is INVALID for an entire2D tile bounding interval: gaps between its row
   spans contain other tiles. Use a contiguous tile-row-span cache or otherwise
   prove membership. Cover multi-row linear spans, first/last partial tiles,
   negative/out-of-range writes,1x17, odd widths, and all legal surface bounds.
4. Validate BOTH full borrowed planes and every rectangle/token/history before
   ANY GL query/upload/mutation. Keep metadata-only retention and synchronous
   borrowed lifetimes, original coverage->RGB->world/present ordering, final draw
   and capture, and ACK only after successful presentation. A later plane/upload
   failure must poison the partially changed backend; no silent retry or ACK.
5. Upload subrectangles without full-plane packing/copying. WebGL2 typed-array
   texSubImage2D supports source offsets and UNPACK_ROW_LENGTH/SKIP parameters;
   their units/constraints and restoration need actual GPU proof for RGBA8 and
   R32F. Preserve pixel-store/bindings/active unit and existing error checks.
   Avoid conflating TexImageSource rules with ArrayBufferView rules.
6. Differentially compare against literal full upload across held/unsubmitted
   frames, fades/death/sleep, region changes, overlapping/transparent writers,
   source mutation, duplicate/stale ACKs, resize and owner swaps. Require exact
   current RGB/T planes and final pixels. Existing affine composition approximates
   some legacy integer rounding; this work must not silently change that behavior.
7. Then test actual current-source Firefox static AND strict six-family combat,
   spell/summon visuals, loading, interaction/picking, and matched warmed OFF/ON
   cohorts with identical key/layout controls. Verify actual bytes/calls and CPU
   marking overhead alongside frame percentiles/FPS. Defaults remain manager-owned.

A later CPU-overlay step could reuse precise write coverage to avoid full RGB/T
clears or move raster operations across the browser boundary. CPU dirty history
must include unsubmitted frames and is NOT the GPU ACK history. That is a separate
ownership change. A complete UI-command rewrite is a larger correctness project
than the presently demonstrated transport bottleneck; it is not first here.
