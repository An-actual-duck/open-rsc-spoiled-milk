Private browser segmented model kernel
======================================

Scope and reason
----------------
This is a private, default-OFF architecture experiment. It amortizes browser
native-call overhead by borrowing up to 128 models' primitive-array references
per call. It does not pack/copy vertex values, change culling/picking/camera
rules, drop effects, reduce visual quality or alter normal desktop defaults.
The manager observed hundreds of small calls/frame in the separate per-model
prototype and no balanced improvement. That earlier topic/artifact remains
parked, not imported wholesale here. No FPS gain is claimed for this candidate.

The numeric loop is an explicit internal salvage of the authored algorithm at
85c632c4a054fd7a103ad69559129e0cd9e2dac2 in browser-native-model-kernel.js.
The frozen-reference exporter is also reused from that internal topic, with
an added same-camera mode for packet testing. No third-party game assets or
runtime implementation were copied into this repository.

Producer and ownership boundary
-------------------------------
Scene owns a BrowserBatchedModelKernel only when the private startup property
spoiledmilk.browserBatchedModelKernel is true. Its capability additionally
requires actual browser presentation. Native/default/software frames keep the
literal Java path. RSModel.rotate1024 itself remains byte-for-byte unchanged;
new package-local helpers only inspect cache-clean bounds or borrow 8 array
references. m_Yb!=0 and interaction-only models are never deferred.

Before the original model loop Scene begins a packet context. Cache-clean
eligible models are queued; before dirty/unsupported/null/proxy models Scene
flushes previous packets and executes the original rotate and interaction-only
scan in their original order. The last packet is flushed before m_T's unchanged
literal transform and before all consumers of projected model arrays. finally
clears packet references on success, fallback and Java-visible failure. A
fatal native JavaScript thread stop is not proven to unwind Java finally;
such a failed private session must be torn down. Application JS still retains
no borrowed references. There is no new
cross-thread source-mutation contract; the packet is render-thread-owned.

A packet contains at most 128 model references, 8 existing primitive-array
references/model, counts/visibility and 8 camera / 6 coefficient integers. Only
O(models) metadata/reference storage is prepared. No source or output vertex
array is copied for transport. Clean frustum-excluded models are metadata-only
entries (no array reads), and clean visible zero-vertex models need no numeric
work. Entirely metadata-only packets commit in Java without JNI.

Visibility m_dc changes are deferred until whole-packet success. A native
representation rejection promises zero writes, then replays the packet through
the literal Java method in order. Dirty reset/normal computation and unsupported
exceptions therefore still occur after all earlier transforms. Proxies remain
barriers, preserving the immediate interaction-only scan and later occlusion
logic. Model membership, world chunks, sprite aggregate and rendering order
remain independently owned by the original code.

Aliases, coefficients and errors
--------------------------------
Java guards all active row lengths/nulls and local output aliases. A bounded
IdentityHashMap tracks cross-model reader/writer roles; reader/reader sharing
is allowed, writer/reader or writer/writer conflicts create a literal barrier.
Writers of FastMath.trigTable1024 also stay literal. The coefficient table is
captured afresh per segment after the preceding fallback; even an empty flush
clears cached coefficients before a rejected model can modify the trig table.

The native callback receives the original trig table as read-only storage as
well as the compact copied coefficients. It validates the ENTIRE packet before
any write, including Int32Array representation, lengths and ArrayBuffer range
conflicts against all source/writer/config/table storage. Range unions are
conservative and may reject safe gaps; they cannot authorize an overlapping
writer. Unsupported packets return false with no changes. The synchronous
callback retains no arrays after return and does not introduce per-model
Promises or Java callbacks. Unexpected backend failures are fail-closed; no
assumption is made that a JavaScript throw becomes a Java Throwable.

Near<=0 or unsupported camera/trig setups retain original exception behavior.
The numeric kernel uses Math.imul, signed 32-bit wrapping/shifts and truncation
for exact Java integer results. It only writes existing projected/rotated arrays.

Private controls and work receipts
----------------------------------
Only WebGL benchmark URLs parse modelbatch=on/off, default off. Ordinary and
software URLs do not set this property. Scene reports actual capability through
isBrowserBatchedModelKernelEnabled; requesting ON with an old JAR missing the
getter is explicitly rejected by the private bootstrap.

browserProof.batchedModelKernelWork is actual native JS work: attempts,
successful packets/models/vertices, metadata rows, rejections and max packet
size. browserProof.batchedModelPreparationWork comes from the actual Java
producer once/second and reports 14 saturating counters: frames, groups, native
packets/models/vertices, metadata/literal models, rejected packets, alias/dirty
barriers, queued models/maxGroup, queued array references and role-map operations.
These distinguish enabled-but-unused from useful granularity. Counters are
not vertex values, gameplay authority or GPU elapsed-time measurements.

Startup observer correction
---------------------------
The first actual game ON attempt exposed an observer startup bug: mudclient
exists before its Scene, but the new optional work observer dereferenced Scene
unconditionally. The observer now captures Scene once, omits work receipts
until it exists, and retains explicit errors for absent/invalid ready getters.
It does not report the candidate enabled before an actual Scene is available.
The startup fixture executes requested/disabled pre-Scene, ready, replacement,
missing/wrong-type/short/null counters and failing-getter paths. The tools suite
also checks that all observer Scene reads use a single captured reference.
The kernel, packet arithmetic and client classes are unchanged by this fix;
previous immutable stages and failed manager evidence remain preserved.
