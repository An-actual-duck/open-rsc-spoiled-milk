Browser fresh scenery projection experiment
===========================================

Status: CPU-correct default-OFF experiment; matched browser timing showed no
benefit. Manager will park this implementation unmerged. Dynamic spell/projectile/
summon parity remains a separate broader browser gate.
Base authority: 325bf42b60fe411705f9f14c0a3ef6debabe24a7.

Private property spoiledmilk.browserSceneryProjectionWork defaults false.
Scene.isBrowserSceneryProjectionWorkEnabled() reports requested eligibility AND
existing full browser GPU/model-bound ownership. It does not claim every model
or frame can defer projection. Separate private harness sceneryprojection=on|off
routing belongs to the manager's benchmark-tools topic.

Original RSModel.rotate1024 remains literal. The new sibling first performs the
same transform-cache refresh, frustum test and integer XYZ camera rotation. It
collects exact int-shifted numerator extrema and positive depth extrema during
that same current-frame traversal. Four numerator/depth corners per axis bound
all signed Java integer-division results. Existing outward scale padding remains
the authority; viewport Y addition wrap, near-plane mixtures, incomplete arrays,
small models and unproven bounds fall back. Per-vertex extrema use int
comparisons rather than Math helper calls. No long arithmetic on the hot path.

Only full GPU-owned scenery is eligible. Actor/sprite m_T, interaction-only
proxies, native/software/mixed/CPU-depth/editor and forced legacy are excluded.
Only early-cull picking frames use the experiment; late cull remains literal. Fresh XYZ and visibility are always
available; projected XY are delayed only for a model wholly outside the mouse
envelope. Scene checks each omitted face uses current rotated vertices. A null,
short, invalid or spare-capacity face materializes exact same-frame projection
before executing the original face/error path. This includes late-cull mode:
proven faces skip before any old projected-XY consumer. Frame-local boolean
storage is bounded by existing Scene model capacity and is overwritten each
eligible frame; there is no camera/geometry/picking cache.

The proposed CPU oracle independently compiles frozen325 Scene, RSModel and
ProjectedModelPickBounds. It compares actual Scene picks, occlusion/order,
anchors, resident payloads and pixels across moving geometry/topology/material,
changing camera/zoom/near plane, interaction proxy, GPU/mixed/software/depth and
forced fallback. Separate direct current-coordinate cases include negative and
extreme XYZ, camera offsets/rotations, Java shift wrapping, viewport addition
wrap, huge pick scales, near clipping and malformed array exception fallback.
Test-only isolated source instrumentation counts projected/omitted vertices and
actual perspective plus added interval divisions;
no production counters/timers are added. The original method literal is checked.

Expected work reduction is perspective divisions/stores for rejected scenery,
not transform refresh/normals, fresh XYZ rotations, actor projection/compositing,
resident input construction or packing. Candidate bounds plus a second projection
pass can cost more for mouse-near models. Actual matched browser measurement is
required; no FPS gain or60FPS claim follows from CPU parity/work counters.

Ownership and alias/error review
-------------------------------
Before any split work, malformed/incomplete arrays retain the literal original
method and exception/mutation sequence. After the unchanged transform refresh,
all reordered output arrays must be independent of source/transformed arrays,
each other and observable material/topology/light payloads. Nested faceIndices
and faceParam1 rows are reference-checked without reading unsafe vertex indices.
This single post-refresh alias walk avoids a duplicate O(face-capacity) scan.
The original fallback call is OUTSIDE the refresh try/catch, avoiding duplicate
GenUtil error wrapping. Its second refresh does nothing to the state that the
unchanged first refresh already completed; independent tests cover m_Yb states
0/1/2/3/-1/Integer.MIN_VALUE/Integer.MAX_VALUE and compare final alias mutations
and error text, not merely pixels.

Maintained ownership scope: RSModel.setFaceVertexCount and
clearRotDataAndParams26 allocate fresh projection and XYZ arrays; capacity growth
uses owned Arrays.copyOf, and clone/combine constructors route through allocation.
Production-source assignment audit found no cross-model assignment of those
package-private output arrays. No global O(models²) scan is introduced to support
arbitrary reflection-created cross-model shared output graphs. Per-model alias
hardening covers the current writer/read ordering; it is not a claim that all
possible hostile external object graphs are supported.

Manager matched hardware result: do not adopt
--------------------------------------------
The manager measured this exact implementation (06f2e601b) using one immutable
projection-only candidate JAR identified as 29855329 and the 206 literal ASYNC
frontend. No height/cache/native call experiment was enabled. Both fresh runs
used 180 seconds warm-up then two 30-second measurement phases, exactly 32 NPCs and
37 actor groups, camera 112/512/0 and welcome modal off. ON ran before OFF; desktop
applications were unchanged and task CPU/GPU activity was exclusive.

Projection ON: 46.269452497584055 FPS; phase p95 = 23/23 ms, p99 = 26/26 ms.
Projection OFF: 46.98590422873138 FPS; phase p95 = 23/23 ms, p99 = 25/25 ms.
Both runs had zero frame intervals over 33 ms. ON versus OFF is -1.524822695035466%.

This matched idle-world comparison shows no performance benefit and a small
regression in this run. It does not establish a general causal regression from
one ON-then-OFF ordering, but it provides no reason to adopt the candidate. CPU
correctness and deterministic division-work reduction passed; those do not imply
lower actual browser frame time. Preserve the branch and its evidence, leave the
property default OFF, and park the implementation unmerged. No tuning was made in
response to these measurements.
