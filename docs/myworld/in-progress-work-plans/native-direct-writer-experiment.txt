Direct native compact writer: populated-route follow-up
=======================================================
Recorded November 14, 2026 UTC. This is a separate follow-up to the frozen
native-compact-transition-experiment.txt campaign, not a pooled replacement.

Decision
--------
Retain the bounded prototype with nativeCompactGeometry and
nativeCompactTypedWriter both default OFF. Direct integer writing removes much
of the old compact encoder's CPU overhead and retains the exact 50% observed
geometry-upload/residency saving. It does NOT yet establish a reliable native
transition improvement. No browser FPS gain, weaker-machine gain, first-coherent
world latency improvement, publication, merge or deployment is claimed.

A real default-OFF regression was found in populated travel despite reassuring
warmed microbenchmarks. It has been repaired by isolating the experiment from
literal legacy/native and browser field writers. Final low-overhead OFF runs
match the frozen legacy range. The new test enforces identical instructions in
six original packing routines, allowing only constant-pool index renumbering.

Both -Dspoiledmilk.nativeCompactGeometry=true and
-Dspoiledmilk.nativeCompactTypedWriter=true are required for direct writing.
BrowserBenchmark and browserPublicAlpha ignore these native controls. Eligible
paths require native atlas UVs, resident shader, unbaked directional material
lighting and no projected shadow-proof path. Unsupported configurations retain
the original float stream. Requested representation still participates in cache
matching; the direct and roundtrip encoders produce the same representation.

The 52-byte vertex retains eight float components: position, atlas UV and normals.
Nineteen exact byte fields come from their original integer sources, including
material and terrain RGB, base legacy light, kind/family/mask, blend strength and
constant unbaked texture light. It avoids normalizing these integers to floats and
then reconstructing/admitting byte values. Existing legacy-light clamping and
24-bit RGB extraction remain the source semantics. The typed destination itself
rejects out-of-range IDs, masks and strengths rather than truncating them.
Nonfinite float fields reject, and negative zero in float fields is retained.
A late rejected vertex regenerates the entire legacy chunk, never a mixed prefix.

Default-path repair
-------------------
The earlier ed847d87e candidate shared per-vertex representation selection with
the float writer. Three low-overhead OFF routes had worst gaps 307.604, 323.849
and 246.614 ms, versus 224.897 and 221.590 ms in the frozen 5820ee21d3 baseline.
Two OFF runs had 189.842/205.996 ms maximum chunk-upload phases versus about
92 ms baseline. The separate instrumented OFF run did not reproduce those stalls;
its faster timings cannot dismiss the low-overhead failures.

The repaired writer dispatches once per chunk. Legacy/native and browser float
routines are literal baseline implementations; unsupported or rejected direct
packing returns to the original writer. Small output-writing paths deliberately
remain separate so experimentation does not add per-vertex branches to default
or browser execution. Shared material/source helpers still supply authoritative
inputs. Independent full-JAR parity tests cover both destination implementations
and protect against future drift. No precise JIT-cause claim is made.

Measurement contract and memory
-------------------------------
The two cohorts contain 41,173 and 25,258 unique cadence intervals, respectively.
All 21 fresh runs share verified server cd21a4abdd61738fd3130b7b78590ec57fd0339d,
map/seed, harness sources/compiled classes, route and quality settings. Captures
have 1920x1080 content viewport, Remaster directional lighting, SMOOTH geometry,
High shadows, daytime, fog ON, zoom 75/rotation 128, and matching final inventories
of 17 received players, 40 NPCs, 780 game objects and 25 wall objects. Six adjacent
walks, long teleport, level change and return are exercised. This populated route
uses visual projectile emitters, not authoritative real-combat testing.

Hardware is the accelerated RX 6700 XT on the owner's existing CPU/OS and Java 8.
No concurrent native playtest client was observed. The repository GPU lock is used.
No quality, distance or geometry reduction was intentionally made. Real GPU pixel
and shadow-depth fixtures provide the independent representation correctness proof.
These runs do not establish benefit on an integrated GPU, a weaker PC or a browser.

112 -> 52 bytes per vertex is 53.57%; with both unchanged index streams, the matched
upload is 141,441,120 -> 70,720,560 bytes and resident geometry is
465,035,040 -> 232,517,520 bytes, both exactly 50%. Retained direct scratch grows
17,825,792 -> 26,214,400 bytes because the legacy fallback buffer remains beside
compact scratch. This is not total GPU/driver memory or a total CPU-memory saving;
old replaced buffers awaiting GC and temporary arrays/maps are excluded. No cache
residency increase or contention redesign follows from these results.
