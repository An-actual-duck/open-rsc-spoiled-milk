Browser stationary Scene projection reuse — PARKED, default OFF

FINAL MANAGER DECISION: DO NOT ADOPT. READY is for preservation/parking only,
not ordinary renderer integration. Firefox testing did not isolate sufficient
comparable-workload gain to justify this added cache/validation complexity.


Measured target supplied by manager: Firefox ModelRotate around3.1ms within
Scene around6.7ms. Existing model-pick bounds reject faces only AFTER rotating
all model vertices. A preprojection world-AABB rejection was not chosen: public/
package-mutated geometry, stale bounds, int wrap and near clipping would require
additional conservative proof. This candidate skips no geometry/picks. It reuses
only exactlyverified prior integer projection results for a stationary camera.

Implementation:
- Scene-owned BrowserProjectionReuse enabled only by startup property
  spoiledmilk.browserProjectionReuse=true AND browser full GPU ownership,
  skip-projected-capture and no forced complete software frame. Default is OFF,
  allocating no cache. Native/CPUdepth/mixed/forced frames use literal old path.
- All camera offsets, three rotations, perspective shift, near threshold and six
  actual mutable trig table entries form the camera key. Moving/new camera clears
  entries, no model copy/admission; two consecutive identical camera frames admit.
- RSModel.rotate1024 original body is literally unchanged (source guard). A new
  optional wrapper can hit only for m_Yb0, for which resetTransformCache(7972) is
  an exact no-op, and after reproducing the original visible-frustum test. Dirty
  transforms, malformed parameters and misses call the old method. The sprite
  anchor model m_T always stays on the old path.
- Owned copies of ALL active transformed XYZ values are compared, no hash or
  transform-revision trust. On a hit, all five projection arrays are bulkrestored,
  repairing even externallymutated output arrays. Original writes all five active
  arrays even behind the near plane (shift path), so this does not overwrite any
  active unwritten state. Off-frustum original leaves outputs untouched; no hit
  or capture occurs there. Sparecapacity outputs are not overwritten.
- Guard null/short arrays, out-of-range counts, input/output aliases and output/
  output aliases: original interleaved writes/exceptions remain authoritative.
- Entry copy budget8MiB, <=256 entries,16..8192vertices/model. All eight int arrays
  plus512bytes/entry conservative header/map overhead are accounted; fixed helper
  pose scratch/map baseline is separate small bounded storage. Full active hotset
  refuses new admission, neverevicts activeentries to cycle Scene order. End-frame
  prune removes unseen/offscreen/dirty/retired keys; individual/batched removals
  and removeAllGameObjects release entries immediately. Disabled backend/native/
  CPUdepth nextdraw clears entries; Stop/sessionVM teardown releases Scene.
- Saturating int counters avoid CheerpJ long arithmetic. Private1Hz receipt has
  actualScene getter enabled plus hits,eligiblemisses,entries,bytes,admissionrejects.
  These diagnostics are render-owned counters, not authority or frame timestamps.
