Measured reason for this slice
The manager's fixed mixed-actor/normal-camera diagnostic profile attributes about
4.315ms to resident-object append, within22.08ms source work; actor groups and pose
were stable. This does NOT establish that temporary descriptor objects account
for the whole append span. Source inspection found a concrete repeated operation:
captureResidentStaticInputs constructs a ResidentObjectCanonicalIdentity for each
static live/virtual record, calls writeDescriptor to copy its8 integers into the
existing bounded probe, and discards the object immediately. A typical scene has
more than1000 such records. The fresh terrain sampling remains necessary.

Change
The original creator and uncached/native builder are untouched. At the start of
the browser's existing descriptor capture, a private default-OFF policy chooses
a direct collector. It uses the same object eligibility/classification, animated
index collection, live/virtual ordering and8-int format. Its direct writer copies
the creator's exact elevation/dimension/direction/int-overflow arithmetic and
writes into the existing owned probe without constructing the temporary identity.
There is no extra height cache, source hash, revision assumption or model cache.
Animated pose handling, canonical grouping, actual mesh construction, probe bounds,
relog/region invalidation and all uncached/native paths retain their old behavior.
The OFF collector remains its original body after one policy check per capture;
it gains no per-record wrapper dispatch. No new production counters were added.

Control and receipt
spoiledmilk.browserResidentDescriptorWriting=true explicitly opts in. Default is
false. mudclient.isBrowserResidentDescriptorWritingEnabled() reports actual flag,
existing resident-input cache eligibility, installed browser presentation and the
existing debug/geometry diagnostic exclusions. Separately coordinated ai-1 owns
private query/Bootstrap receipt wiring. Ordinary native/software remains on the
old path. The static flag is selected at startup, not changed during gameplay.

Duplicated sampling arithmetic is deliberate: the native creator stays the
reference path. A source assertion verifies that original creator and uncached
builder are byte-for-byte unchanged from frozen325bf. Another assertion requires
the copied arithmetic in the direct writer to stay textually aligned. Future
sampler changes must update both intentionally and rerun the independent oracle.

frozen325bf mudclient and candidate default/OFF/ON, with test-only constructor-entry
instrumentation in temporary source files. Production classes have no counter.

Coverage includes more than1100 presentation records, live/wall/animated inputs,
