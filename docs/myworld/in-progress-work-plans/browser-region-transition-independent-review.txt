Independent oracle design for the forthcoming focused change
------------------------------------------------------------
Freeze exact baseline and candidate sources; compare recording-backend float raw
bits/index/material bytes, draw order/IDs/offsets, mutation isolation and thrown
error traces. Exercise a sequence with shared regions, repeated forward/backward
crossings, return after LRU pressure, and signed-level/world/package changes.
Keep same-location fresh immutable geometry distinguishable from equal labels.
Settings-only, texture pixel-only, texture dimension/average/alpha changes,
missing materials, dynamic pose and topology updates must preserve old invalidation
semantics. Include zero/oversized first chunks and mandatory animation so new
work cannot starve. All cached geometry/source arrays need explicit ownership and
bounded lifetime. Upload/replace/delete failure must not commit cache accounting,
masquerade as a current pose, or publish partial readiness. Domain-level backend
errors may execute a valid prefix, but cannot produce a successful current-world
ACK or continue an incoherent session.

If scheduling is incremental, explicitly prove resume/cancel tokens bind immutable
source+settings+material/world/level identity, stale prepared work cannot publish,
reset/logout/dispose releases it, and old-current resources remain usable until
replacement successfully completes. Test the64MiB worker producer command cap
alongside the per-vertex budget: larger/reordered resource bursts can exhaust the
transport even while Java/GPU cache budgets individually fit. Result queries can
split packets; resource prefixes cannot disappear during a skipped draw.

candidate packer to agree with itself. Headless JVM CPU fixture elapsed time is

and actual continuous route timing remain manager gates.
