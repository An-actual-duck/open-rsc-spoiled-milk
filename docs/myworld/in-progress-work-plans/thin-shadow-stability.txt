Cause and bounded implementation
High's far map covered192tiles at2048 pixels:12world units per depth texel,
versus4 for the near map. Actual railing material12 has repeated bars about5projected world units wide
in the controlled orientation, plus1/2pixel alpha details. Width depends on
quad orientation/UV and sun projection. Binary nearest-sampled alpha during
caster rasterization therefore changes coverage as the sun rotates. Fixed-sun /
fixed-camera output is stable, while cached-far refresh changes cause large
thin-shadow area steps. Receiver PCF cannot restore absent caster coverage.

High now uses4096 far maps (6world units/texel) where GL_MAX_TEXTURE_SIZE permits,
with2048 capability fallback. The near map, filter kernel, alpha cutoff and bias
are unchanged. Pose-only far refreshes transition from the previous completed
map over12 rendered frames (~0.2s at60FPS). Texture/projection commit together
after a successful draw. This interpolates two valid visibility fields rather
than removing/fading the thin shadows to hide them.

History is never blended across static geometry/material signature changes,
roof coverage changes, active planes, render-context epochs, Low/Off, gated /
empty frames or session cleanup. Renderer context epochs advance only from the
existing true applyLayeredSceneScope(scopeChanged) path; each published frame
stores an immutable epoch. No packet, readiness, authority or worldspace rule
changes. Same-geometry scope changes therefore still hard-cut old history.

Fixed-sun TTL rebuilds do not create unnecessary history (normalized sun vector
comparison tolerance1e-6). Rapid pose rebuilds reuse exactly two far allocations;
no recursive history layers or unbounded trail accumulation. Scope/content
changes immediately use the new map. Low frees both far maps. Off/gated paths
free previous history and invalidate the current projection; bounded current
map storage may remain cached, but is rebuilt before reuse. Cleanup frees all.

A4096 D24 map commonly occupies64MiB. High's near+current+previous maximum is
about144MiB versus the old32MiB (driver storage dependent). The second far
texture is allocated on later refreshes and retained bounded in High. The2048
capability fallback is about48MiB with history; Low remains about4MiB. During an
active transition
there is one additional far9-tap PCF sample, for at most12frames per refresh.
The coherent diagnostic snapshot preserves its first9 fields and appends:
9farMapSize,10historyActive,11blendPermille. CPU observer updates are optional;
normal clients retain disabled diagnostics by default.

Animated-alpha follow-up required by native evidence
The first native rotating-camera case revealed1453far rebuilds/58s after a
texture became loaded. A matched49f baseline has exactly the same late onset
and1453builds, proving this was inherited rather than introduced by history.
CPU audit found existing Scene.d scrolling animation: it replaces RGBA texture
snapshots each update once a resource is loaded. Actual material17 contains
moving transparent pixels; the old full-RGBA static signature therefore had to
invalidate every frame, preventing the fence's far transition from operating.

Candidate 2 records generic immutable animation intent from Scene.d, including
when the resource is not loaded/has been evicted, and preserves it through
palette/resource factories. RGB/alpha bytes, their content signatures and game
animation remain unchanged. The shadow renderer has no material-ID special case.
A shared predicate excludes only animated-alpha materials from BOTH cached far
caster draws and far signatures. They continue casting in the every-frame near
map, matching the established near-only animated-scenery policy. Opaque RGB-only
animation remains far eligible because its depth coverage is static. Static
railings12/timber10 remain eligible unchanged. No animated-alpha far history is
blended or ghosted; this is a cache-ownership correction, not a global opacity
reduction. Old/native candidate1 metrics below are superseded by candidate2.

Temporal evidence (RX6700XT; not FPS acceptance)
The controlled shader uses actual production shadow code. Cases separate fixed
sun/camera, subpixel camera pan, normal cached-sun refresh, signature-forced
rebuilds, cascade blending and camera-eye rotation. Integrated receiver shadow
area tracks coverage; camera residuals are reprojected before comparison, not
just same-pixel image differences. Opaque and close controls prevent a false
stability win from removing the thin shadows.

- Old2048 cached-far mean area4168; maximum frame step1627 (~39%).
-4096 alone mean6351; maximum step755 (~12%).

  absolute step than the old baseline. The analytic pre-bias cutout reference
  is128*192*(4444/16384)=6666; receiver bias reduces that expected area slightly.
  New coverage is restored toward this reference, not reduced to make it stable.
- Close native control mean5944.83 is unchanged. Fixed sun/camera is bit-stable.

Signature-forced every-frame rebuilds intentionally remain hard-cut, because
those signals represent content changes. The transition is not a promise that
arbitrarily changing geometry or every possible subpixel texture can be made
perfectly stationary. Camera-only minification still has finite sampling error;
we do not claim to eliminate it across every distance/view.
