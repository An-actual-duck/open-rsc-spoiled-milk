Browser layer-return crash repair — November 12, 2026

Problem and change
------------------
Returning down the ladder near global (257, 539, level 1) to level 0
failed with: Whole-RAM carrier basis must align to48tiles: offset=2304,832.
The upper-level carrier is valid for ordinary layered terrain; it is not a
valid whole-overworld RAM carrier. No rounding or relaxed alignment is needed.

World.setLayeredTerrainScope calls its retained-mesh transition before committing
the incoming terrain and carrier offsets. That transition passed the incoming
level-0 snapshot to forWorld, whose provider then read the still-current upper
carrier from World. It combined two different scopes and threw.

The single production change uses the existing forCaptured API at this precommit
decision, pairing incoming terrain with incoming offsets and roof option. The
same API already owns captured-input prebuild and halo admission. It validates
source identity, page roster, protocol, tile size, roof option and alignment.
This decision only clears retained meshes. It neither publishes a prepared frame
nor performs activation. The later actual loadSections/compose forWorld checks
are unchanged, including current native/browser ownership, patches and settings.
The World setter's commit order, strict WholeRamBasis constructor, asynchronous
publication guards, and all native fallback paths remain unchanged.
