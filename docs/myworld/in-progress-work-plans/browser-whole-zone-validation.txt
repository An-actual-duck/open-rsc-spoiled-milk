Planned independent candidate gates (pending stable runtime APIs)
----------------------------------------------------------------
1. SOURCE / DELIVERY: exact selected package, full source roster and settings/
   actual texture catalogue bind the baked manifest. Reject stale source/model/
   material/packing settings, malformed counts, path escapes, missing/duplicate
   records, checksum failures and budgets. Membership is checked against the
   independent roster, not declared cell totals alone. Record raw-source CPU
   residency, canonical CPU geometry and pinned GPU bytes as DIFFERENT states.
2. GEOMETRY: compare representative actual producer output against the frozen
   ordinary production path, including every 112B vertex field/raw Float32 bits,
   indices/material batches, lighting normals, roof/indoor/shadow descriptors and
   actual texture resolution. Include route boundary 111,623↔624, adjacent sector
   seams, negative Y, uniform 250 edges, invisible wall materials and sloped/
   stacked upper-floor structures. Audit floor-local topology counts alone are
   insufficient for actual stacked-world coordinates. Validate bake ownership:
   positive-stitch 48 and canonical 24 are alternatives; adjacent cells may not
   double-paint seam triangles or omit blend/normal dependencies.
3. DYNAMIC / USE: construct real authoritative object-cell inputs through the
   existing key builder. Equal canonical key must select pinned IDs and skip
   local static upload. Mutating/removing a door, destroyed last object/explicit
   empty cell, animated current pose, source epoch and negative-cell ownership
   must mask every stale baked triangle exactly once and use the current live
   geometry. A border-crossing object needs a consistent anchor-cell policy.
   Wrong/incomplete authoritative rows must refuse, not leave old scenery drawn.
4. GPU / LIFETIME: root executes an actual hardware full-catalog allocation,
   complete membership/resource hash and final synchronization gate before
   cover release. Exact representative pixels compare ordinary renderer versus
   catalogue path with the SAME shader/material/lighting/sky settings. Check
   returned/caller-buffer reuse, late fetch/hash/upload failure cleanup, resource
   disposal and context-loss refusal. CPU mocks do not establish actual VRAM fit,
   GPU completion, image equality or scanout latency.
5. TRAVEL / PERFORMANCE: after source+geometry+full GPU acceptance, use the same
   artifact whole-zoneON/OFF and original minimap walking helper on the existing
   private fixture. Initial preload and zone-entry wait are recorded separately;
   the owner explicitly may accept an upfront wait. Record full expected/loaded/
   CPU/GPU-ready cells/bytes, actual pinned triangles/draws, local static uploads/
   repacks, exact override reasons, held/fresh frames, source authority and queue
   age. Unchanged crossings may not regenerate every active static cell as an
   override. Include longer routes and separate teleports/mutations. Retained
   screenshots are not fresh-world FPS; counters alone do not prove visible use.

Proposed nonrunning stage approach
----------------------------------
Use maintained scripts/browser-gameplay/prepare-repeatable-client.py for the
loopback 43649/43549 browserdemo fixture. It already validates the private marker,
32-NPC fixture and exact immutable JAR source receipt, with Cache/port 43649. Root
may use the preserved original walking driver; do not create a replacement DB
or modify the running fixture just for this test.

A split candidate needs explicit per-file composite provenance: prepare.py copies
frontend and Bootstrap from its own checkout, whereas --native-source only binds
native-dispatch inputs. It must not accidentally serve main's old JS/Bootstrap
beside new Java natives. Freeze exact ai1 Java/bake/source settings and exact ai2
frontend/catalog blobs with hashes; never label the composite one nonexistent
commit. A full build/stage from ai1 or manager-reviewed source copy is preferable
to a partial JAR overlay. Root owns actual HTTP/Firefox launch.

The earlier standalone three-way Worker oracle is reusable for renderer pixel/
physical-output/ownership cases, but its toy fixed scene cannot prove full-zone
catalog allocation, seam/roof geometry or use across the world. A new full-data
hardware gate is required; package-source proof and computed byte totals alone
are not a substitute. Keep partial/failing receipts and never silently fall back
to broad caching or normal rendering while labelling the result whole-zone.
