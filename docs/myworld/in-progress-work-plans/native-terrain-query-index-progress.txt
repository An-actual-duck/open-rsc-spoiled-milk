Change
------
Add the separate opt-in spoiledmilk.nativeTerrainQueryIndex to the existing pure
Java terrain slot/bounds implementation. Browser policy retains its original
getter and behavior. Both flags default false in ordinary native startup.
Regular validated rosters use exact indexed lookup; mixed-size rosters retain
ordered scanning. There is no new retained terrain cache or per-query allocation.

Measured native outcome — November 13
-------------------------------------
After Stardew fully exited, six fresh native JVM/fixture runs completed in order
OFF/ON/ON/OFF/OFF/ON, each with 20-second warmup and 30-second busy-camera phase.
The same frozen candidate JAR was used, with explicit policy receipts. Evidence:
output/diagnostics/native-terrain-query-index/cohort-20261113T052741Z/results.json.
All runs retained 435,422 resident triangles, 17 received players and 40 received
NPCs (including controlled summons); no partial records or fixture failures.
Median of the three run means, OFF -> ON: sceneRender 1.341038 -> 1.349153 ms;
OpenGL CPU render 3.540794 -> 3.578020 ms; world submission 0.806532 -> 0.822298 ms.
These small differences establish no useful improvement in this workload.
Both modes stayed capped at approximately 16.667 ms offscreen intervals.
This does not certify visible presentation or weaker hardware. Background desktop
applications and idle older private servers remained, documented in machine.json;
no competing game renderer, heavy build or profiler was deliberately run.

Decision: retain the independent opt-in and exact correctness proof on this
preserved research branch; do not enable it in launcher defaults or publish a
performance claim. Loading/construction-heavy comparisons could revisit it later,
but the next active candidate is static scenery input-group reuse.

Future acceptance if revisited
-----------------------------
Use the same frozen candidate JAR with explicit native OFF/ON so the one startup
policy is the only client-source difference. Fresh disposable fixtures per run;
1920x1080, normal zoom75, identical map/assets, quality, sun, fog and warmup.
Run three interleaved pairs OFF/ON, ON/OFF, OFF/ON with no competing games,
builds or heavy profiler. Start with busy-camera, then travel/transition and real
combat controls if attribution supports the change. Preserve policy receipts,
actual content counts, raw stage/cadence tails, memory and machine/runtime data.
Do not infer overall FPS improvements from lookup-only synthetic measurements.
Maximum zoom is a separate stress case; retain the ordinary visible playtest.

Next independent CPU candidate remains static resident input-group reuse.
The current native path rebuilds grouping maps despite unchanged descriptors;
the browser cache compares fresh canonical identities, heights, memberships,
anchor/base/settings and revisions, rebuilding animated groups. A future native
port must prove actual native cache use, mutable-input invalidation and literal
OFF mesh parity; do not impersonate browser presentation to enable it. Do not
bundle it into this candidate before collecting the lookup comparison.

Follow the larger standalone-rendering-and-chunk-loading-plan.txt for compact
native geometry and coherent budgeted uploads. Those steps are not implemented
by this prototype. A READY research handoff does not mean default adoption or a
release approval; this branch is intended to be parked with evidence retained.
