SPOILED MILK ASSET AND OUTPUT ORGANIZATION
Adopted with the owner on November 2, 2026.

ONE VISUAL LIBRARY
  dev/myworld/assets/runtime/     game-ready files; the client packages this tree
  dev/myworld/assets/authoring/   editable masters, source inputs, recipes, provenance
  dev/myworld/assets/references/  preserved examples and contact sheets
  dev/myworld/assets/CREDITS.txt existing attribution record

Use the role first and the subject second. Game UI has one lowercase home:
assets/runtime/ui/{magic,prayer,cleric,summon,equipment,slayer,world-editor}.
Equipment, items, NPCs and world sprites live under runtime/sprites/.
Runtime animations keep their three established rendering categories. The
legacy specialty-animation fallback has the explicit name legacy-animations.

All feature-art projects formerly beside assets/ now live under authoring/.
The original PNGs, Aseprite masters, source inputs and approval records remain.
Historical intake paths/versioned hashes remain historical; production paths
identify the current files. Do not rewrite old provenance as a new intake.

The remastered source workspace lives under authoring/remastered-sprites/.
Its generate command publishes only the explicit ready catalog and frame PNGs
to runtime/remastered-sprites/; work frames, descriptors, incoming deliveries,
templates and references do not enter the client. Its hidden/default-off state
and contributor attribution are unchanged.

A source asset is not a generated preview. Keep editable work in authoring/;
put working exports and comparisons under output/art/ or output/reviews/;
promote approved bytes deliberately into runtime/. Existing curated approval
records are preserved rather than discarded as scratch.

CATEGORIZED GENERATED OUTPUT
  output/art/<subject>/          sprite exports, compositions and previews
  output/reviews/<topic>/        related review images/reports/logs together
  output/tests/<suite>/<run>/    classes, fixtures, test databases and results
  output/diagnostics/<topic>/    captures, profiles and static analysis
  output/builds/<tool>/          compiled development tools and build markers
  output/releases/<version>/    Java/Windows/world release archives
  output/cache/<tool>/           reusable downloads and Java runtimes
  output/benchmarks/<suite>/     measurements
  output/logs/                   general command logs; job logs stay with the job
  output/archive/<topic>/        indexed historical outputs
  output/scratch/<experiment>/   temporary experiments, never the sole art master

A job may contain several file formats. Keep its inputs/frames/report/logs
coherent rather than splitting it into global folders by extension. Name
repeatable review/diagnostic runs explicitly. Do not create another task folder
or loose image directly under output/.

The machine-readable contract is config/workspace-layout.json. Resolve a path:
  python3 scripts/workspace-layout.py path reviews my-feature/run-001 --mkdir
  python3 scripts/workspace-layout.py path tests my-feature --mkdir
Validate placement and exercise preservation checks:
  make asset-output-check
  python3 scripts/workspace-layout.py check

The check rejects duplicate UI/asset hierarchies, authoring/work files in
runtime assets, new feature folders under dev/myworld, unclassified output
roots and ad hoc output defaults in maintained producer scripts/build files.
AGENTS.md records the rule for future contributors and AI workers. The combined
test runner includes the layout test and a final placement check.

RELOCATION AND HISTORY
Existing output folders can be inspected and relocated without deletion:
  python3 scripts/workspace-layout.py migrate-output
  python3 scripts/workspace-layout.py migrate-output --apply
This is a one-time workspace operation, not an automatic cleanup. It preserves
file identities/bytes and records old/new paths plus inventories under
output/archive/layout-migrations/. It rejects active files, escaping/absolute symlinks, unclassified folders and
destination collisions. Relative links wholly inside a moved tree (such as JRE
license links) retain their exact link targets and are verified after moving.
Review an old worker's outputs when it next receives this source version; do
not delete them merely because they predate the current structure.

Tracked historical battleaxe review evidence was moved out of ignored output/
to docs/myworld/evidence/battleaxe-coatings-phase1/. Its bytes remain unchanged.
The sourcePathMigrations and legacyOutputPaths tables resolve historical source
and output references. Old exact-commit reports keep their original evidence.
The asset/output reorganization itself is versioned in Git; it does not retag
or modify any published release or public deployment.
