Startup/ABI evidence and limitations
------------------------------------
Stage2 exited1 before any kernel calls/phase events. Cause remains unlocalized;
no ABI conclusion follows. Stage3 changed diagnostics AND serving to the existing
range-capable server, then passed DEBUG exact tests. That does not isolate which
change affected startup. Debug capture has zero timing rows and is excluded from
cost comparisons. Early Java entry/font/catch diagnostics and bounded console
capture remain; clean runs disable enableDebug.

Clean probe3:57,620 exact C-int/T-raw-Float32 words, immediate Java reads after
native return. Probe4:10,368,000 exact words after groups across all five glyph
counts and both native controls. Both completed30 timing cohorts, no errors,
poison or rejection. Total actual native calls747,226 and409,408 respectively,
including warmup/gates/timing. Genuine Int8 font,Int32 C/metadata,Float32 T views
were observed; distinct zero-offset output ArrayBuffers are compatible with the
accepted range-alias guard. Full C and T each contain518,400 elements/2,073,600
bytes. Real runs needed no ArrayBuffer adapters (adaptedBuffers0).

zeroCopyBorrow states that our adapters share incoming storage, not a measurement
of every runtime internal operation. Official conversion docs describe these
primitive arrays by reference. Empirical same-call exact reads demonstrate actual
visibility; cost sensitivity adds evidence, not proof of all runtime copy behavior.
No pixel/source/proxy is retained by the native module; only scalar view metadata,
counters and integer scratch are long-lived. No await/GL occurs inside the kernel.

----------------------------------------------------------
Includes common clear, Java packet building for native modes, fresh borrow,
dispatch/adaptation, ALL-packet preflight and raster. Literal is not charged
artificial packet building. Common clear is once per group, NOT once per TEXT in
probe4. Each mode/count/order has about0.5seconds aggregated wall measurement.
These are API/kernel costs, not gameplay FPS, GPU time or bus bandwidth.

0.761/0.764; at128,literal1.307/1.286 versus native1.209/1.176.0-glyph control adds
roughly8–10us/callback in both tests. Large buffers do not show an obvious full-
surface-copy-sized added tax per call in these shapes; small/full differ clear
and group structure, so this is not an isolated copy benchmark or a causal proof.

No confidence intervals or broad platform coverage; synthetic plots, fixed font,
short reversed-order samples and common setup constrain extrapolation. Multiple
calls can cost more than the literal arithmetic they replace. No production
transport bounds/written receipt or actual game's callback frequency is measured.
Thus neither successful ABI nor128-glyph win authorizes a per-TEXT game pilot.
