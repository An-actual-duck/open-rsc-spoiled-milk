## Six candidates and controlled edits

- `ichor-water`: deep-purple palette substitution on existing water.
- `divine-water-water`: pale-blue **Divine Water**, same original ripple pattern.
- `ichor-stone-seep` / `ichor-dirt-seep`.
- `divine-water-stone-seep` / `divine-water-dirt-seep`.

Water uses only an ordered one-to-one palette transformation; no pixels move and
no ripple geometry is added. Walls retain every original pixel outside the
stored masks. Short fissures seek the existing dark crack pixels, feeding three
thin, staggered gravity-descending rivulets that reach the base. The changed
areas are a localized liquid seam/flow, not a background material recolor.
These are first art candidates; the pattern strength/spacing awaits owner review.

`generate.py` is the controlled pixel authoring recipe. `author.lua` assembles
six editable Aseprite documents with an untouched native-source layer and a
separate recolor/seep layer. Masks, PNGs and native-size/3× nearest comparisons
are retained. The Lua recipe is checked in and deterministically generated by
Python; Aseprite is used to create/export the actual editable documents.

Reproduce from repository root (Pillow and the already-installed Aseprite):

```sh
PYTHONWARNINGS=ignore python3 dev/myworld/cleric-wells/generate.py
mkdir -p /tmp/cleric-well-preview-classes
javac -cp Client_Base/build -d /tmp/cleric-well-preview-classes \
  dev/myworld/cleric-wells/WellTexturePreview.java
java -Xmx256m -XX:+UseSerialGC -Djava.awt.headless=true \
  -cp /tmp/cleric-well-preview-classes:Client_Base/build \
  orsc.graphics.three.WellTexturePreview dev/myworld/cleric-wells
```

The preview uses maintained `Scene`, `RSModel`, software texture loading and
rasterization. It opens no game session, maps, accounts or sockets. It is not
OpenGL/gameplay proof and does not replace owner in-game art acceptance. Existing
`Client_Base/build` must be available; this task did not rebuild the client.
